# 1. Scrum

**Définition :**

Scrum est avant tout un cadre méthodologique agile pour gérer des projets complexes. Cependant, il existe des rôles dans Scrum :

- **Scrum Master :** Personne qui facilite le processus Scrum, élimine les obstacles et assure le respect des principes agiles.
- **Équipe Scrum :** Groupe multidisciplinaire (développeurs, testeurs, designers, etc.) responsable de la réalisation des tâches.

**Exemple :**

"Le Scrum Master organise la réunion quotidienne (Daily Scrum) pour suivre l'avancement de l'équipe."

# 2. Epic

**Définition :**

Un Epic (Épopée) est une grande fonctionnalité ou un objectif utilisateur qui est trop vaste pour être réalisé en un seul sprint. Il est généralement découpé en user stories plus petites.

**Exemple :**

"Créer un système de paiement en ligne sécurisé" est un Epic. Il pourra être divisé en user stories comme "Ajouter un panier d'achat" ou "Intégrer PayPal".

# 3. Sprint

**Définition :**

Un Sprint est une période de temps fixe (généralement 2 à 4 semaines) pendant laquelle l'équipe réalise un ensemble de tâches sélectionnées dans le Backlog. À la fin, un incrément fonctionnel du produit est livré.

**Exemple :**

"Le Sprint 3 durera du 1ᵉʳ au 15 juin et se concentrera sur l'amélioration de l'interface utilisateur."

# 4. User Story

**Définition :**

Une User Story (Histoire utilisateur) est une description simple et concise d'une fonctionnalité, formulée du point de vue de l'utilisateur final. Elle suit souvent le format :

"En tant que [type d'utilisateur], je veux [action] afin de [bénéfice]."

**Exemple :**

"En tant qu'utilisateur, je veux réinitialiser mon mot de passe pour accéder à mon compte si je l'oublie."

# 5. Issue

**Définition :**

Une Issue (Problème/Tâche) désigne tout élément à traiter dans un projet : un bug, une tâche technique, une amélioration, etc. Les issues sont souvent gérées via des outils comme Jira ou Trello.

**Exemple :**

"L'issue #45 concerne l'erreur de chargement de la page d'accueil sur mobile."

# 6. Backlog

**Définition :**

Le Backlog est une liste priorisée de toutes les fonctionnalités, tâches, améliorations ou corrections à faire dans un projet. Il est divisé en :

- **Product Backlog :** Géré par le Product Owner, il contient toutes les exigences du produit.
- **Sprint Backlog :** Tâches sélectionnées pour le Sprint en cours.

**Exemple :**

"Le Product Owner a priorisé la user story 'Ajouter un mode sombre' en haut du Product Backlog."
